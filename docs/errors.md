# 错误

库用一个错误枚举表达失败。命令行把同一结构打成 JSON，写到 stderr，并以非零退出码结束。成功时 stdout 只放约定的成功载荷，不混进错误对象。

## 输出形状

```json
{
  "ok": false,
  "error": {
    "code": "InvalidField",
    "message": "x starts at 0",
    "path": "ops[16].x",
    "objectId": "slide:1/shape:10"
  }
}
```

`code` 是稳定字符串，给程序认。取值与退出码见下表，不随语言变。`message` 是给人看的短句，按语言渲染，默认英文。
示例是默认英文；请求带 `locale: zh-CN` 时这一句是「x 从 0 起」。
`path` 是可选的 JSON 指针风格路径，指向入参里出错的字段；定位不到就省略。apply 出错时 `path` 仍指向该条 op 里的字段，例如 `ops[16].x`。
apply 出错时还可以有 `objectId` 与 `objectName`。两个字段都在构造该条 op 的错误时读取，读不到就省略。

- `objectId` 是该条 op 的 `id` 原值，不解析、不换成内部编号。
- `objectName` 只在该条 op 的顶层 JSON 有字符串字段 `name` 时出现，值就是这个原值。
  语义跟该 op 自己的 `name`，不读包，不解释成 `p:cNvPr/@name`。
- 不枚举哪些 op 带 `name`。除 pptx 的版式名、节名、系列名外，docx 的 `InsertDocPartOp.name` 是构建基块名，xlsx 的 `InsertProtectedRangeOp.name` 是保护区域名，列清单会漏。

负坐标这类字段错误在 `parse_off_at` 解析期就能报，此时 `parse_ops` 手里只有 `ops`，拿不到包内名字，所以包内名字不能当 `objectName` 的来源。
`objectId` 与 `objectName` 不参与语言渲染，也不影响 `code` 与退出码。

`Io` 错误还可以带可选字段 `osMessage`，放操作系统给的原文。它的语言由系统决定，我们不承诺是哪一门，也不要用它做字符串匹配。只有系统确实给了原文时才出现。

```json
{
  "ok": false,
  "error": {
    "code": "Io",
    "message": "Cannot access \"C:\\nope\\missing.xlsx\" (os error 3)",
    "osMessage": "系统找不到指定的路径。"
  }
}
```

## 语言

`message` 的语言按下面的优先级决定。渲染发生在最外层，库的 `run()` 仍返回语言中立的错误。

| 优先级 | 来源 | 形式 |
| --- | --- | --- |
| 1 | 请求 | 可选字段 `locale` |
| 2 | 命令行 | `--lang` |
| 3 | 环境变量 | `OOXP_LANG` |
| 4 | 默认 | `en` |

`ooxp mcp --lang` 走第 2 档，和普通命令行的 `--lang` 同一优先级。没带 `--lang` 时，错误文案走第 1 档和第 3 档。自己另写的外部 MCP 只能走第 1 档。

第一期只做 `en` 与 `zh-CN`。语言标签宽松匹配：先按连字符切开取首段，再看后面的地区或字形段。
`zh`、`zh-CN`、`zh-Hans`、`zh-SG` 归到中文；`en`、`en-US`、`en-GB` 归到英文；`ja`、空串、乱码以及其它不认识的标签都退回英文，**不报错**。语言是呈现偏好，为了一个不认识的标签把整个文档操作拒掉，代价不成比例。

`Error` 的 `Display` 恒用英文。这是 Rust 的 `Display` 不带参数导致的：`unwrap()` 的 panic 和上层 `anyhow` 打印都是英文。要中文请走 `to_json(lang)`。

## 错误码

- **`InvalidJson`**（退出码 2）
  - 入参不是 JSON，或缺 `action`
- **`UnsupportedSchema`**（退出码 2）
  - `schemaVersion` 不是 `1`
- **`UnsupportedAction`**（退出码 2）
  - `action` 不是 `inspect` / `create` / `apply` / `exportMedia` / `exportChartData` / `exportChartImage` / `exportSparklineImage` / `exportSheetImage` / `exportSlideImage` / `exportPageImage` / `layoutCheck` / `help`
- **`UnsupportedFormat`**（退出码 2）
  - 扩展名或 `format` 不是 `xlsx` / `xlsm` / `docx` / `pptx`
- **`UnsupportedOp`**（退出码 2）
  - apply 遇到第一期不认识的 `op`
- **`InvalidField`**（退出码 2）
  - 字段类型不对、互斥字段同时出现、sheet 名非法、对不上格式的 op 或 scope 键
  - docx create 只给 `password`、不给限制编辑种类
  - 字符串含有 XML 不允许的字符。`path` 指向该字段，例如 `ops[2].text`、`workbook.sheets[0].cells[3].value`。文案带码位，例如 `U+000B`
  - `run_bytes` 做 inspect、apply、exportMedia、exportChartData、exportChartImage、exportSparklineImage、exportSheetImage、exportSlideImage、exportPageImage 时没带上包字节。不带 `path`。英文是 `Package bytes are required`，中文是 `缺少文件字节`
- **`InvalidRange`**（退出码 2）
  - A1 区域解析失败，或起止颠倒
- **`InvalidId`**（退出码 2）
  - id 字符串不符合该格式的生成规则
- **`IdNotFound`**（退出码 3）
  - id 语法对，但文件里没有这个

    - 段落
    - 节

    - 形状

    - SmartArt
    - 嵌入对象
    - 3D 模型
    - 墨迹画布
    - 水印

    - 书签
    - 域
    - 目录
    - 题注
    - 交叉引用
    - 索引
    - 索引项
    - 书目源
    - 引文
    - 书目块
    - 构建基块
    - 嵌入字体
    - 公式
    - 拼音
    - 内容控件
    - 编号实例
    - 抽象编号
    - 样式
    - 数据验证规则
    - 条件格式规则
    - 工作表表格
    - 透视表
    - 定义名
    - 自定义视图
    - 自定义属性
    - 迷你图组
    - 允许编辑区域
    - 自定义放映
    - Zoom
- **`ScopeRequired`**（退出码 2）
  - inspect 要单元格却没给 `sheet`+`range`，要段落正文却没给 `from`+`maxParas`，或要形状却没给 `slide`
- **`TruncatedLimit`**（退出码 2）
  - `maxCells`、`maxParas`、`maxShapes` 超出允许范围，例如设成 `0`
  - `setShapeFormat` 的 `sz` 大于 400000
- **`OpcOpen`**（退出码 3）
  - 不是 ZIP，或缺少 `[Content_Types].xml` / 根关系
  - 条目声明的未压缩大小达到压缩后大小的 4096 倍，或压缩后为 0 且声明大于 0
  - 解压读到的字节超过中央目录声明的未压缩大小
  - 折叠后相同的部件名出现两次
- **`OpcPartMissing`**（退出码 3）
  - 入口部件不存在，目标工作表或幻灯片部件不存在，关系 id 找不到，或者关系指向外部资源
- **`XmlBroken`**（退出码 3）
  - 目标部件不是能解析的 XML
  - xlsx 里 `t="s"` 的索引越界或不是整数
  - create 写文本时共享字符串表里没有对应项
- **`Io`**（退出码 4）
  - 读盘、写盘、创建目录失败
- **`NotImplemented`**（退出码 2）
  - Strict 包（`http://purl.oclc.org/ooxml/`）上的 apply。只读动作照常。请先用 Office 另存为 Transitional
  - 第一期明确不做的动作
  - 目前：对数据表公式范围内非主格发 `setCell`，或对主格写 `value` / 清空 / `shared` / `array`

  - 对墨迹批注发 `setCommentText` / `replyComment`，或在墨迹批注内插图 / 插图表 / 插 SmartArt / 插删段

  - 对透视图表发 `setChartSeries` / `addChartSeries` / `deleteChartSeries` / `setChartType`
  - `setChartType` 不能无损转换
  - `regionMap` 地图 chartex
  - xlsx 图表公式落不到格子上，或新值个数和格子数不同。含长度对不上的并集，以及求成一个数的定义名
  - `setSmartArtLayout` 当前 uniqueId 不在库内 `list` / `org` / `cycle` 三族里
  - 对图表工作表上仅剩的那张图发 `deleteChart`
  - 对 `dialogsheet` / `macrosheet` 发下列 op，以及批注 op、文本框 op、形状与连接线 op、SmartArt op
    - `deleteSheet`
    - `renameSheet`
    - `moveSheet`
    - `setSheetHidden`
    - `setPrintSetup`
    - `setSheetView`
    - `setAutoFilter`
    - `setSortState`
    - `groupRows`
    - `ungroupRows`
    - `groupCols`
    - `ungroupCols`
    - `setOutline`
    - `setRowHidden`
    - `setColHidden`
  - `deletePara` 碰到跨段书签 / 批注范围 / 许可范围、段内修订标记、或非文档末的分节符
  - `setParaText` 碰到段内本期收入的修订节点
  - 段内本期收入的 `w:hyperlink`
  - 段内本期收入的域
  - 段内本期收入的公式
  - 段内本期收入的拼音
  - 段内本期收入的行内内容控件
  - docx 表格结构 op 碰到表/行/单元格上的修订痕迹、网格变更标记，或某行占的列数对不上 `colCount`
  - 目标 `writeProtection` 已有密码哈希却不给对得上的 `writePassword` 就要改对应字段
  - `p:modifyVerifier` / docx / xlsx 已有密码哈希却不给对得上的 `password`

### 各码在具体 op 上的判定

- 找不到单元格时，`setCell`、`setCellStyle` 与 `setCellNamedStyle` 的语义是新建该单元格，因此空单元格不是 `IdNotFound`
- 找不到工作表才是 `IdNotFound`
- `inspect` 的 `scope.sheet` 点名 `chartsheet` / `dialogsheet` / `macrosheet` 报 `InvalidField`
- 下列 op 的 id 是工作表
  - `setColWidth`
  - `setRowHeight`
  - `mergeRange`
  - `unmergeRange`
  - `insertDataValidation`
  - `insertConditionalFormat`
  - `insertSheetTable`
  - `insertPivotTable`
- 找不到工作表才是 `IdNotFound`，单格 `mergeRange`、缺少 `width`/`bestFit`、或数据验证缺 `type` / `sqref` / 必要公式是 `InvalidField`
- `setDataValidation` / `deleteDataValidation` 的 id 是 `sheet:{name}/dv:{n}`
- 序号不存在报 `IdNotFound`，不是规则 id 报 `InvalidId`
- `setConditionalFormat` / `deleteConditionalFormat` 的 id 是 `sheet:{name}/cf:{n}`
- 序号不存在报 `IdNotFound`，不是规则 id 报 `InvalidId`
- 条件格式缺 `type` / `sqref` / 必要公式、`text` 或阈值、或 `type` 不是本期可写类型，是 `InvalidField`
- `setSheetTable` / `deleteSheetTable` 的 id 是 `sheet:{name}/table:{n}`
- 序号不存在报 `IdNotFound`，不是表格 id 报 `InvalidId`
- 工作表表格缺 `ref`、`ref` 少于两行一列、与已有表相交、表名或列名非法，是 `InvalidField`
- `insertPivotTable` 的 id 是工作表
- `setPivotTable` / `deletePivotTable` 的 id 是 `sheet:{name}/pivot:{n}`
- 序号不存在报 `IdNotFound`，不是透视表 id 报 `InvalidId`
- 透视表缺 `source` / `location` / `values`、源少于两行一列、源与主体相交、字段名对不上表头、同一列名出现在两个轴上、或源不是工作表缓存，是 `InvalidField`
- `insertDefinedName` 的 id 是 `xlsx:workbook`
- 不是则报 `InvalidId`
- `setDefinedName` / `deleteDefinedName` 的 id 是 `name:{n}`
- 序号不存在报 `IdNotFound`，不是定义名 id 报 `InvalidId`

- `localSheet` 找不到对应表报 `IdNotFound`
- `setSheetBackground` 的 id 是 `sheet:{name}`，且该表是 `worksheet`
- 找不到工作表才是 `IdNotFound`，单元格 id、图 id 或页眉图 id 报 `InvalidId`
- 对 `chartsheet` / `dialogsheet` / `macrosheet` 报 `InvalidField`
- `deleteSheetBackground` 的 id 是 `sheet:{name}/background`
- 这张表没有背景报 `IdNotFound`，不是背景图 id 报 `InvalidId`
- `setPrintSetup` 的 id 是工作表
- 找不到工作表才是 `IdNotFound`，不是工作表 id 报 `InvalidId`
- 除 op 与 id 外一个字段都不给、边距为负、`orientation` 不是 `portrait`/`landscape`、`scale` 不在 10–400、`printArea` 不是单一 A1， 或对 `chartsheet` 发它没有的字段，是 `InvalidField`

- `exportMedia` 找不到图、嵌入对象、3D 模型、墨迹画布或媒体报 `IdNotFound`

- `exportSparklineImage` 找不到迷你图组报 `IdNotFound`

- docx 与 pptx 上发 `exportSheetImage` 报 `InvalidField`

## 成功形态

inspect 成功：stdout 是领域树，见 [json-contract.md](json-contract.md) 与 [json-contract-xlsx.md](json-contract-xlsx.md) 等分册。
不要再包一层 `{ "ok": true, "tree": ... }`，以免和树本身的字段打架。

create / apply / exportMedia / exportChartData / exportChartImage / exportSparklineImage / exportSheetImage / exportSlideImage / exportPageImage 成功：stdout 为一行 JSON：

```json
{
  "ok": true,
  "path": "C:\\out\\book.xlsx",
  "opsApplied": 3
}
```

`opsApplied` 仅 apply 出现，等于实际执行的 op 条数。create、`exportMedia`、`exportChartData`、`exportChartImage`、`exportSparklineImage`、`exportSheetImage`、`exportSlideImage` 与 `exportPageImage` 省略该字段。

apply 带 `dryRun: true` 时成功响应不带 `path`，也不写文件。它带 `dryRun: true`、`opsApplied` 和 `parts`，`parts` 是本批标脏的部件名数组：

```json
{
  "ok": true,
  "dryRun": true,
  "opsApplied": 3,
  "parts": ["/ppt/slides/slide1.xml", "/ppt/slides/_rels/slide1.xml.rels"]
}
```

`parts` 按部件名排序，去重。没有标脏部件时是空数组。`dryRun` 失败时仍走错误形态，`objectId` 与 `objectName` 按本文开头的规则给。

`layoutCheck` 成功：stdout 是几何检查结果 JSON，不带 `ok`、不带 `path`。它不写文件，详见 [json-contract.md](json-contract.md#layoutcheck)。

```json

  "ok": true,
  "path": "C:\\out\\logo.png",

```
